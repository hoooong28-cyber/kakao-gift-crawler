# 리빙 전체 TOP 200 확대 및 트렌드 통합 탭 정리

- 트렌드 요약·차트에서 전체 통합을 제거하고 리빙 전체를 기본으로 선택한다. 마케팅 카드와 동일하게 네 개의 공식 카테고리 랭킹을 구분한다. 다른 화면의 합산 선택을 가져오지 않으며 화면별 마지막 선택을 기억한다.
- 실제 랭킹 화면이 사용하는 공개 category-tab/search 데이터에서 navId=5의 리빙 전체 200개를 수집했다. 팬시/문구/취미·침구/패브릭·주방/식기는 기존 각 50개다. 오늘 총 관측은 350건이며 카테고리 간 중복은 원본 관측으로 보존한다.
- 실제 수집일은 2026-11-03, 랭킹 API 갱신 표시는 11.03 14:00이다. 리빙의 상품 ID 200개가 고유하며 순위 1~200이 연속임을 확인했다. 광고 전용 API의 삽입 상품은 수집하지 않는다.
- 공개 API의 순서와 상품 ID·이름·브랜드·표시 가격을 사용한다. 중복 ID, 잘못된 상품, 부족한 개수, 페이지 간 갱신 시각 변경은 수집 실패로 처리한다.
- 오늘의 CSV·정적 JSON·카드·누적 이력·IP 시계열·주간/월간 보고서를 다시 생성했다. 이전 58일의 날짜별 JSON은 바이트 단위로 보존했다. 과거 수집 범위를 200개로 부풀리지 않는다.
- 이전 Top 50의 범위 밖에서 처음 관측한 51~200위를 임의로 NEW로 처리하지 않는다. 기간 모멘텀은 기존 공통 수집 범위 계산을 사용하여 수집 확대에 따른 가짜 성장·하락을 줄인다. 일별 IP 시계열의 비중은 각 날짜의 실제 수집 개수가 분모다.
- 매일 자동 수집은 리빙 200개/세부 각 50개로 설정했다. 배포 검증에서 리빙 200개와 연속 순위·상품 ID 고유성을 검사한다. 수집과 배포 날짜는 한국 시간 기준이다.
- 수집 코드 변경 시에도 자동 수집을 실행한다. 배포 데이터는 GitHub 작업에서 공개 API로 다시 생성·검증하고, 검증한 docs 산출물을 공식 Pages 액션으로 배포한다. 자동 커밋만으로 Pages가 갱신되지 않는 문제도 방지한다. 로컬 검증의 갱신 표시는 14:00이며 실제 배포본은 배포 작업 실행 시각에 재수집한 결과다.
- API 요청·페이지 처리·불완전 수집 차단, 화면별 기본 범위·복귀 동작, 50→200 시계열 분모를 테스트한다. 기존 순위 비교·기간 집계·저장 날짜 렌더링 회귀 검사도 실행했다.

실행: `python main.py --top_n 50 --living_top_n 200`
