# 급상승 라이징 스타 중복 조사 및 수정

기준 커밋: `3b378c0` (2026-10-28 수집 데이터). 2026-10-29 배포 사이트에서 재현.

## 재현과 판정

마케팅 인사이트 카드 → 전체 통합 → Card 4에서 상품 `11734230`이 1위 NEW와 1위 +32로 두 번, `14506119`가 2위 NEW와 4위 NEW로 두 번 표시된다. 5행에 고유 상품은 3개다.

이는 공동 순위가 아니다. 서로 다른 카테고리의 로컬 순위와 동일 상품의 다중 카테고리 노출을 하나의 순위 표로 표시한 결과다. 53개 날짜 JSON 전체에서 `(카테고리, 상품 ID)` 중복과 `(카테고리, 순위)` 중복은 각각 0건이다. 기존 날짜별 카드 중 동일 상품이 반복된 카드는 21개다.

## 원인 경로

- 수집 `crawler.py`: 카테고리별 `seen_ids`로 링크 중복을 제거하고 `rank=1`부터 순차 부여한다. 같은 상품이 여러 카테고리에 등장하는 것은 정상적인 관측이다. 이 수집 순위는 카카오의 공동 순위 여부를 따로 수집하는 구조가 아니다.
- 비교 `rank_comparison.py`: `(category, product_id)`를 기준으로 직전 수집일의 순위와 비교한다. 키링은 리빙에서 NEW, 팬시에서 33→1위(+32)로 서로 다른 올바른 비교를 가진다.
- 누적 `update_master_history`: 같은 날짜를 교체하고 날짜별 기록을 누적한다. 라이징 카드는 하루 데이터에서 계산되므로 마스터 이력의 날짜 합산이 직접 원인은 아니다.
- 집계 `analytics.py`: 전체 카테고리 기록을 합친 뒤 상품 ID로 묶지 않고 `rank`만 정렬하여 5행을 잘랐다. 동일 상품이 슬롯을 여러 개 차지했다.
- 대체 계산 `docs/app.js`: 중복 제거, 정렬, 5개 제한 없이 후보를 추가했고 category와 product_id도 잃었다.
- 렌더링: 카테고리 정보 없이 로컬 `rank`를 ‘순위’로 표시하여 공동 순위처럼 보였다.
- 정적 배포 `main.py` 및 GitHub Actions: 계산된 카드를 일별 JSON과 최신 JSON에 저장하여 같은 문제가 과거 날짜에도 유지됐다.

## 수정 동작

`rising_stars.py`와 `DashboardMetrics.risingStars`는 NEW 또는 10계단 이상 상승한 유효 후보를 카테고리 순위, 카테고리명, 상품 ID 순으로 정렬한다. 상품 ID(없으면 검증된 카카오 상품 URL)로 묶고 중복 제거 후 최대 5개 상품을 선택한다. 이름이 같아도 ID가 다른 상품은 합치지 않는다. 비교 불가·ID 불명·잘못된 순위는 제외한다.

동일 상품의 **조건을 충족한** 카테고리별 순위와 변동폭은 `ranking_contexts`에 보존한다. 표의 ‘번호’는 1~5 표시 순서이고 ‘카테고리별 순위 · 변동’에 실제 관측 순위와 NEW/+변동을 표시한다. 개별 카테고리 필터는 해당 카테고리 기록만 사용한다. 글로벌 순위나 공동 순위로 재해석하지 않는다.

서버 카드와 브라우저 대체 계산을 같은 규칙으로 맞췄다. 과거 형식의 카드가 남아도 선택 날짜의 원본 기록으로 표를 다시 계산한다. 54개 데이터 JSON(53개 날짜+최신)과 최신 별도 카드 파일을 재생성했다. 원본 `records`, CSV, 순위 비교 결과, 다른 카드 집계는 보존했다. 매일 배포 검증에도 라이징 카드 일치 검사를 추가했다.
